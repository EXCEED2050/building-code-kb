# 广州试用数据核对记录（2026-10-22）

本轮由 Codex 逐页查看本地 PDF 图像并与转录对照，覆盖验收题引用的 **15 条不同条文**。结果为：5 条未发现转录差异，10 条已按原件校订。先前隔离的3条抗震文字已完成续页及2016修订标记核对并校订；只解除文字隔离，仍保留旧版来源及整本2024文本未合并的提示。工程人员复核及签认尚未完成，不能将此记录称为人工验收通过，也不能推及整本规范。

原始 JSONL 的 `status` 仍为“待核”。校订保存在 `data/catalog/verification.json`，记录原 PDF 的 SHA256、PDF 页序、原转录内容指纹、校订内容及理由。应用装载时套用校订；若转录内容变化导致指纹不符，该条自动暂停用于 AI 作答，防止旧校订误套到新数据。原始快照保留，便于复查和撤回。

在项目根目录运行`building-kb check-reviews`，可复核15条记录的原始转录指纹、5份定位PDF、2024抗震补充修订件及完整阅读本的指纹和核对页序。它只能验证记录仍对应这些文件，不能替代逐页视觉检查。

- Python回归检查20项通过，覆盖逐轮检索、同一规范的新条号、新规范全名、主题保留、范围歧义、缺失条号、错误年份、指纹失效、PDF跳页及鉴权等。`node tests/check_ui.js`通过，覆盖普通／方括号引用、逐轮定位、版本歧义和表格转义。
- 真实HTTP检查通过：无口令访问401，完整PDF可返回，定位副本P43重定向完整本P51，原副本页图仍可用。指纹变化或完整本缺失会明确报错，不套用错误页码。

- 本机浏览器另检查真实生成答案、条号追问、两轮各自依据、引用定位、刷新恢复、无依据轮次保存，浏览器实际打开完整PDF为51/136页。每轮问题／答案／命中条文快照保存在本浏览器，可导出JSON；新查询替换当前组，不是公司服务器归档。

## 完整PDF恢复

`data/catalog/source_documents.json`记录分卷及生成PDF指纹、136页总数与8页偏移。原始分卷恢复后，在项目根目录运行`building-kb build-pdfs`重建完整本，然后运行`building_kb.commands.check_reviews`。逐页预览与条文的P号仍指原66页定位副本；“整本PDF”按映射打开，例如7.3.1原P43→完整P51，7.4.7表原P46→完整P54。
