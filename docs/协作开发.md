# 两人协作开发

## 首次接手

1. 先获取 `EXCEED2050/building-code-kb` 的应用代码。安装方式见根目录 README。
2. 私有仓库主分支已附 159 本规范的完整切条结果与台账，先运行 `python -m tools.check_snapshot` 核验快照。
3. 在项目 `kb/` 目录执行 `python run_dev.py`，输入启动日志中的随机口令。
4. 先验证条号查询和关键词查询。AI 作答需自己配置模型密钥；向量检索需下载完整 embedding 模型并建立索引。

原件和 OCR 下载及恢复见 [私有资料恢复](私有资料恢复.md)，字段见 [数据格式](数据格式.md)，分工与待办见 [开发计划](开发计划.md)。原先的 16 本公开子集仍保留，范围与来源见 [公开数据说明](../kb/public-data/README.md)。

完整私有快照包含 159 个条文文件、43,813 个块及 329 条台账记录，快照日期为 2026-10-20；检索池为 28,440 块。块数包含正文、条文说明和修订记录，不代表全部块都进入检索池。主分支可直接检索，恢复原件附件后再核验 PDF 预览。

## 按工作内容取得资料

| 工作内容 | 所需资料 |
| --- | --- |
| 页面、接口、关键词检索、引用展示 | 应用代码 + 条文库 `kb/data/chunks/` + 台账 `kb/data/catalog.csv` |
| 核对原文与页码、PDF 预览 | 再加原始 `建筑规范/`、对应 `MinerU/` 源文件和 `kb/data/ocr/_merged/` PDF，保持原目录结构 |
| 改进解析、切条与 OCR | 再加相应的 MinerU/OCR 结构化结果、原件、图片；不要仅凭已经切好的条文反推原始排版 |
| 向量与重排 | 安装可选依赖，通过 `python -m tools.get_models` 下载模型，再运行 `python -m src.index` |

本机检查发现 `bge-m3` 目录缺少权重，不能把该目录存在当成模型可用；下载工具会检查权重是否完整。模型不放进普通 Git 提交，避免两人重复上传大文件。

原件查找会依赖 Word、MinerU/OCR 目录判断来源。仅放台账与条文时可做检索，但不足以保证原件预览完整；搬运资料后可用 `python -m src.source_pdf` 检查页码映射。不要把“能检索”当成“原件全部配齐”。

## 共同修改

- 各自为功能建分支，通过 Pull Request 合并，避免直接覆盖对方修改。
- 改台账订正、引用提醒和处理优先级时，将对应 TSV 与代码一起提交。
- 完整条文与台账在当前私有主分支中追踪；原件和解析资料通过私有 Release 共享。凭据、模型及缓存继续排除，不能将内部资料公开。
- 发布新的数据快照时记录日期、输入来源和内容校验值，双方切换到同一快照再比较检索结果。
- `.env`、访问口令、模型 API 密钥和签名密钥由每人单独配置，不放在共享包里。

## 协作包说明

本地 `协作交付/` 用于准备含真实数据的交付包，已被 `.gitignore` 排除。

- `collaboration-core`：应用代码、架构与协作文档、台账、人工规则、完整切条结果，可用于真实数据检索开发。
- `parsed-text`：MinerU/OCR 的 JSON、Markdown 结果，保留原目录；未包含图片和 PDF，供文本解析调试使用。
- 原始 PDF/Word、OCR 合并 PDF 和解析图片已整理为 7 个独立资料卷，见 [私有资料恢复](私有资料恢复.md)。旧的本地协作包仍可保留，当前交付以私有主分支与该 Release 的清单为准。

数据包附带 SHA256 文件清单，可在解压后核验。清单和数据包也包含内部规范标识，不应上传到公开仓库。
