# 两人协作开发

## 首次接手

1. 克隆仓库，在根目录按 [README](../../README.md) 创建 Python 3.12 环境并执行 `python -m pip install -e .`。
2. 执行 `building-kb check-snapshot`，再执行 `python run_dev.py`。条文查询无需模型密钥。
3. 需要 PDF 预览或改进切条时，按 [资料恢复](../data/私有资料恢复.md)补齐原件和解析资料，目录由工具自动安排。
4. 每人配置自己的根目录 `.env`，不要共享真实密钥。可选模型另行下载到 `var/models/`。

## 按工作内容选择资料

| 工作 | 所需内容 |
| --- | --- |
| 页面、接口、检索、引用展示 | 主分支代码与 `data/chunks/`、`data/catalog/` |
| 原文与页码核对、PDF 预览 | 再恢复 `data/sources/`、`data/processed/`；执行 `building-kb build-pdfs` |
| 解析、切条与 OCR 改进 | 同时取得对应原件、结构化结果和图片 |
| 向量、重排与 AI 解读 | 可选依赖、完整模型或各自的服务端 API 配置 |

主分支完整快照为 159 本、43,813 块，检索池 28,440 块。原件下载项可能含多个版本、分卷和图纸，所以 PDF 附件数量与入库标准数量不同。

## 共同修改

先阅读 [开发与提交规范](../../CONTRIBUTING.md)，执行 `python scripts/setup_dev.py` 安装本仓库的提交钩子。提交使用 `feat:`、`fix:`、`docs:` 等约定式前缀。各自建立功能分支，通过 Pull Request 审阅后合并。修改代码前同步主分支；提交前安装 `requirements-dev.txt`，运行 `python scripts/check.py`。GitHub 会执行同样检查。

台账、人工规则、校订记录和源码一起提交。改变条文快照时同步更新 `data/manifests/runtime-manifest.json` 的大小、SHA256 和汇总数量，保留数据来源与日期；不要只为了检查通过而覆盖原始快照。两人比较效果时应使用同一数据版本。

原件和 OCR 资料通过仓库 Release 共享，恢复后的目录与本地一致。`.env`、真实 OCR 配置、模型、索引、缓存、日志、迁移备份均被 Git 忽略。仓库及 Release 当前公开，新增资料时核实其共享范围。
