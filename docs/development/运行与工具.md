# 运行与维护工具

以下命令在项目根目录、激活 Python 3.12 环境并执行 `python -m pip install -e .` 后运行。`building-kb` 等同于 `python -m building_kb`；各模块也可直接以 `python -m building_kb.<子包>.<模块>` 启动。

## 常用检查和检索

```sh
building-kb search --no-rerank "GB 50016 第5.5.17条"
building-kb check-snapshot
building-kb export-public --check
python -m pip install -r requirements-dev.txt
python scripts/check.py
```

共同检查不调用外部模型。需要本地原件的额外检查是 `building-kb check-reviews` 和 `python -m building_kb.source_pdf`。

## 资料入库

默认目录由 `paths.py` 管理。重新生成台账或切条会写数据文件，先保留原快照，在分支中处理并核对结果。

```sh
building-kb catalog --roots data/sources --out var/catalog-candidate.csv
building-kb queue
building-kb ocr --list var/queues/ocr_t1.txt
building-kb chunk --only "GB 50016-2014"
building-kb review --std "GB 50016-2014" --clause 5.5.17
```

台账候选文件核对后才替换 `data/catalog/catalog.csv`。切条默认读取受控台账，优先 Word，使用 MinerU/OCR/PDF 定位页码。生成校对页在 `var/review/`，不与当前架构文档混放。

本地 OCR 使用 `magic-pdf 1.3.12` 内部接口，应在独立环境安装 `requirements-ocr.txt`，并安装本项目包。复制 `config/magic-pdf.example.json` 为本机 `config/magic-pdf.json`，填写模型绝对路径与设备；也可设置 `MINERU_TOOLS_CONFIG_JSON`。不要直接换装 MinerU 2.x。

云端 OCR 使用 `building-kb ocr-cloud --list var/queues/ocr_t2.txt`，需根目录 `.env` 中的 `MINERU_TOKEN`，会上传 PDF 到 MinerU；`building-kb ocr-cloud --status` 只看进度。任务状态保存在 `data/processed/ocr/_cloud/`，不进入版本管理或资料快照。

## 可选模型

```sh
python -m pip install -r requirements-models.txt
building-kb models
building-kb index
```

模型下载到 `var/models/`，向量库在 `var/index/chroma/`。目录存在不等于模型完整；下载工具会检查权重。`index --rebuild` 会清空并重建当前集合。模型或索引不可用时可只用条号/BM25。

根目录 `.env` 填各自密钥。`KB_EMBED_PROVIDER`、`KB_RERANK_PROVIDER`、`KB_LLM_PROVIDER` 分别控制向量、重排、作答，也可用 `KB_PROVIDER` 统一切换。默认 native 向量与重排、DeepSeek 作答；公网服务会接收问题和相关条文，`local` 为内网/本地 OpenAI 兼容接口。

## 二维码

```sh
python -m pip install 'qrcode[pil]'
building-kb qr https://你的服务域名
```

二维码生成到 `var/qr/`。二维码只编码访问地址；需要另行部署网页和访问认证，其他手机无法访问开发机的 `127.0.0.1`。

## 复现依赖

`requirements.txt` 固定轻量直接依赖；`requirements-tested-py312.txt` 保存原已测环境的完整依赖快照。测试工具在 `requirements-dev.txt`，模型与 OCR 各有单独依赖文件。使用完整快照时先安装它，再执行 `python -m pip install -e . --no-deps`。
