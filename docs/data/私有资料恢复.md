# 私有资料恢复

主分支自带 159 本、43,813 个条文块与 329 条台账记录，可直接进行检索开发。仅阅读 PDF，可从 [PDF 目录](PDF目录.md)逐份下载正常 PDF；需要原目录、Word 和 OCR 加工资料时使用完整资料备份。

## 恢复完整目录

从 [完整资料 Release](https://github.com/EXCEED2050/building-code-kb/releases/tag/data-2026-10-20)下载所需的 ZIP 和该 Release 的 `asset-manifest.json`，放进同一个文件夹。全部 7 卷共约 4.10 GB，解压约 4.60 GB，4,220 个文件；每卷独立，不要按字节拼接。

| 附件 | 新目录 |
| --- | --- |
| `originals-part01.zip` 至 `originals-part03.zip` | `data/sources/` |
| `mineru-part01.zip`、`mineru-part02.zip` | `data/processed/mineru/` |
| `ocr-part01.zip`、`ocr-part02.zip` | `data/processed/ocr/` |

先按根目录 README 安装应用，然后从项目根目录运行：

```sh
building-kb restore /附件文件夹 --check-only
building-kb restore /附件文件夹
building-kb build-pdfs
building-kb check-reviews
python -m building_kb.source_pdf
```

2026-10-20 备份卷里仍是旧目录。恢复工具兼容原清单和新清单，核验旧归档成员的原始大小、SHA256，再自动映射到新目录；**不要手动把旧目录直接解压到工程根目录**。旧 PDF/ZIP 附件和下载链接无需更换。

恢复工具拒绝越界路径、链接文件、清单外文件和同名不同内容的覆盖；已有内容一致时保留。输出缺少的卷名，方便按需补齐。默认目标是该项目，可用 `--root /另一项目` 指定。

`building-kb build-pdfs` 根据 `data/catalog/source_documents.json` 核对已登记分卷，再生成完整阅读本到 `data/processed/reference-pdfs/`。逐页预览仍使用原定位副本，完整本页序通过映射转换。`check-reviews` 需要这些 PDF 已经恢复，未恢复时失败不代表条文检索不可用。

## 文件清单

`data/manifests/runtime-manifest.json` 核验 Git 跟踪的原始条文和台账。目录迁移只更新路径与台账的来源前缀，159 个原始 JSONL 的字节未改。

`data/manifests/asset-manifest.json` 保存大附件清单；`path` 是新目录位置，`archive_path` 是旧 ZIP 中的成员名，卷本身和每个文件的哈希不变。下载附件里的原版清单也可直接使用。

`data/catalog/pdf-catalog.json` 保存 386 个 PDF 来源条目，对应 375 个独立下载文件。部分条目来自原始嵌套压缩包，`!/` 后是包内成员，并非可以直接打开的文件系统路径。完整目录恢复用于应用与重处理，单份 PDF 下载用于直接阅读。

## 各自保留的内容

`.env`、API 密钥、访问口令、签名密钥、真实 OCR 配置、模型、Chroma 索引、页图缓存、云端 OCR `_cloud/` 作业状态和本机归档不上传。队列可按台账重新生成。恢复完整资料不表示 OCR 文字、现行性、修订与全部页码已人工验收。
