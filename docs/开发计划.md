# 协作开发计划

## 当前可接手的范围

- H5 页面、访问口令、Cookie、书目、条文详情和 SSE 查询已有实现。
- 私有主分支有 159 本规范、43,813 个块，过滤后检索池为 28,440 块；16 本公开子集仍保留供对比。
- 模型调用、本机向量与重排已有适配代码；配置依赖、完整模型、索引和密钥后另行验证，不把“代码存在”当成“部署验证通过”。
- PDF 预览与原件定位已有代码，需恢复同仓库的私有原件/OCR 附件后再验收，详见私有资料恢复说明。

## 两人分工建议

| 方向 | 可独立推进的工作 | 合并前检查 |
| --- | --- | --- |
| 页面与接口 | 查询交互、空结果、引用提醒、书目、SSE 错误状态和移动端布局 | 保留 `caveat`；未登录返回 401；模型不可用时仍显示检索结果 |
| 数据与检索 | 条号解析、章节上下文、表格质量、去重、状态与来源核验 | 数据变化可追溯；条号查询不由近似命中替代；不把条文说明当正文 |
| 共同负责 | 来源白名单、接口字段、验收题库和发布 | Pull Request 说明改变了什么、如何验证、还有哪些限制 |

## 优先待办

1. 建立至少 30 个验收问题：10 个条号、10 个关键词、5 个表格、5 个无结果或缺资料场景。预期结果由持有可靠原件的人核对，不让模型自己给自己打分。
2. 核验公开快照各版本的现行状态、修订记录和正文完整性，把问题记录到对应条文，不直接猜改数值。
3. 针对目录误判为“修订”的情况改进切条判据；当前公开导出已排除这些块。用原件和期望条文集合验证修复。
4. 确定可共享原件的获取方式，先配齐一本规范，验证原件路径、PDF 页码和条文引用再扩大范围。
5. 完成模型与向量能力的单独验收，记录设备、依赖版本、模型完整性和索引快照。

## 合并约定

代码功能各建分支，通过 Pull Request 审阅。公开数据变化同时提交 `sources.json`、`manifest.json` 与条文文件；运行 `python -m tools.export_public --check`。完整私有条文变化同时更新 `runtime-manifest.json` 并运行 `python -m tools.check_snapshot`。密钥、全量协作 ZIP、OCR 作业状态、缓存和模型目录继续排除。

文档中的“已实现”描述源代码能力；“已验证”只描述实际执行过的检查。部署、工程使用和真实模型效果分别验收，避免相互替代。
